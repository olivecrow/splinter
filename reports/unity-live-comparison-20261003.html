0.7 연결 실패를 성공 구간과 분리했다

0.7 L은 wildcard 0.0.0.0:7800, 보존 대상 기존 Editor는 127.0.0.1:7800이었다. exact L catalog 실패를 보존했다. C A/B의 0.7 코드·에셋 읽기는 성공했으므로 모든 0.7 동작이 실패했다고 일반화하지 않는다. port 겹침 관측만으로 내부 원인을 확정하지 않는다.

사용자 승인 후 trial L/C/S A/B만 0.8로 맞췄다. CLI upgrade는 manifest 변경 뒤 package resolve/reload·정상 재시작이 필요했다. C B는 이전 descriptor의 port 재사용으로 401 Unauthorized를 겪었고 새 exact-path catalog로 재연결했다. 기존 Editor·패키지는 보존했다.

S A/B의 최초 read·reload 뒤 read 및 A 재개의 첫 read에는 서버 main-thread 5000ms timeout이 있었다. 동일한 읽기 한 번 재시도에서 실제 값을 얻었다. S B status401도 reload 뒤 descriptor를 다시 발견해 해결했다. 쓰기/compile 요청을 timeout만으로 반복하지 않았다.

계측 스크립트의 S A stop 후속 Git 관측에는 process-local XDG trust 설정이 한 번 빠졌다. A Editor가 이미 정상 종료한 상태에서 실패를 기록했고, 기존 실행별 trust를 적용해 같은 작업의 stop을 재조정했다. 구형 기록의 회수 차단과는 다른 실패다. eval의 접근 불가 형식·잘못된 CLI 하위 명령 등 작성 도구 오류도 프로젝트 컴파일 실패로 세지 않았다.

A/B release의 StateCorrupt는 같은 home records 전체 조회에서 구형 73개 기록의 sourceKind/applicationKind 누락으로 발생했다. 새 A/B 기록 deserialization은 유효했다. 구형 state 자동 이관·기존 records 삭제·외부 snapshot 정리·새 home/grant로 우회하지 않았다. 마지막 회수를 완료했다고 표시하지 않는다.
