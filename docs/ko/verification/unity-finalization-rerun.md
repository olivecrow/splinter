종료 행은 RC-01의 정상 종료 116.8초와 직렬 checkpoint/release 199.5초를 합쳤다. Editor 종료는 명령 시작 후 110.661초 / 112.696초에 관측했으며 이미 이 시간에 포함된다. 마지막 Editor 종료 이후는 78.173초이지만 A의 보존 작업과 B의 종료가 겹칠 수 있으므로 독립적으로 분리한 checkpoint/release 측정값은 아니다.

초기 준비는 61.8초 짧아졌고 재컴파일은 11.6초, Library 복원은 13.2초 길어졌다. Editor 기본 로그의 초기 스크립트 컴파일은 127.876초 / 127.065초, 초기화 attribute 처리는 45.587초 / 45.648초였다. 증분 소스 검사는 약 5.2–5.6초였다. 첫 검사에서 변경 파일 하나를 hash하고 1,601개를 재사용했으며, 후속 검사는 1,602개를 모두 재사용했다. 이는 관측이며 각 cache의 효과를 함수별로 분리한 인과 분석은 아니다.

## 입력·방식·시간 경계

소스는 `b09fa58e9d40a560d4fe1af7a213f8ac23e8e3b1` 그대로다. 추적 파일 1,602개 / 2,804,772,822 bytes, Unity 6000.3.22f1이다. 현재 Library는 **42,418개 파일 / 3,141,789,464 bytes**다. SE-01의 원본 Editor가 cache를 갱신했으므로 RC-01과 비교해 17개 파일이 바뀌고 2개가 없으며 추가 파일은 없다. 이전 Library는 42,420개 / 3,141,660,252 bytes였다. 정확한 차이와 hash는 데이터셋에 남긴다. 따라서 과거와의 비교에는 코드·실행 순서와 cache 입력 변화가 함께 포함되며 최적화만 분리한 통제 실험의 절감률은 아니다.

장비는 같은 Windows 11 Home 10.0.26200 / NTFS, Ryzen 5 5600X(6코어 / 12스레드), RAM 68,628,553,728 bytes다. 커밋한 소스는 이미 시험한 고정 LF 실행 파일과 일치한다. 새 Splinter A/B와 현재 Library 기준본을 먼저 실행하고 원본 Library 바이트가 동일하게 복원됐음을 확인한 뒤 공유 Editor를 실행했다. 두 방식은 같은 raw 소스와 현재 Library 입력을 사용했다. 실행 순서는 고정했고 OS cache를 비우지 않았다.

각 작업은 맡은 C# 식을 바꾸고 명시적으로 refresh한 뒤 최신 로드 값, assembly MVID/세대 변화와 컴파일 오류 부재를 확인한다. A의 기대값은 `(5,6,13)`, B는 `(4,9,13)`이다. 같은 기존 외부 검증 probe로 선택 에셋의 GUID·mesh·texture·scene·dependency hash·렌더 preview hash를 확인한다. 공유 Editor는 한 번의 refresh로 A를 복구하면서 B를 적용하고, 마지막에 `(4,6,13)`을 복구·재컴파일한다. 이번 공유 묶음의 후보 준비는 동시 실행하는 Git 스크립트이며 새 Codex 대화나 새 AI 세션 시간을 측정한 것은 아니다. AI 추론과 앱 인계는 양쪽 시간에서 제외한다.

Splinter 계측은 Library 준비부터 최종 복원까지이며 읽기 전용 비교 확인 0.153초를 제외한다. 소스/Library 입력 hash 확인과 최종 검증은 계측 밖이다. 겹친 A/B 구간은 한 번만 센다. 공유 Editor 시간은 워크트리 생성, 실제 후보 편집/보존 구간, 중단 없는 Editor 작업, 소스 병합과 회수를 더한다. 작은 명령 전환 간격은 남으며 대화 전체 경과 시간이 아니다. 새 저장 할당 스캔이나 프로세스 sampling profiler는 실행하지 않았고 기존의 가벼운 provider 관측과 Editor 기본 로그를 보존했다.

## 회수와 한계

Splinter 두 작업은 `released`로 끝났고 독립 결과는 RC-01 결과 tree와 일치한다. 소유 Editor는 exit code 0으로 정상 종료했으며 provider·mount·delta·등록은 부재이고 소유 자원 계수는 0이다. 원본 소스 hash·HEAD·branch·기존 refs/worktree·설정을 보존하고 임시 local raw-EOL 설정을 복구했다. 공유 실행 전에 원본 Library를 모든 입력 파일 바이트가 같은 일반 NTFS로 복원했다.

공유 실행은 원본 소스 1,602개를 복구하고 기준 코드 재컴파일·정상 종료를 확인했으며 코드 워크트리·등록 두 개를 제거했다. Editor가 정상적으로 갱신한 Library cache는 되돌리지 않았다. 양쪽 모두 원본을 덮어쓰지 않고 독립 결과와 같은 충돌 없는 병합 tree `756e0a926577c9bcff036c823b4816b3b2d5fb19`를 보존했다. CLI 응답 13개(실행 명령 8개, schema 조회 5개)는 현재 응답 schema를 통과했다. 서비스·UAC·패키지·전역 설정 변경은 필요하지 않았다.

방식별 한 묶음의 측정이다. Play Mode, Unity 시험, 게임 빌드, 병합 결과 컴파일, 새 독립 Editor 두 개의 Codex 워크트리, 저장 공간 peak, 전체 시스템 RAM, 긴 작업 손익분기는 **미실행**이다. 이전 저장 수치는 RC-01의 입력/버전 경계를 유지하며 FU-01은 시간 비교다.
