# 여러 단계의 Unity 미로 작업

[English](../../verification/unity-maze-workflow.md)

MW-01 · 2026-10-14 · 제품 `07bc2de`. [데이터셋](../../../reports/benchmarks/unity-maze-workflow-20261014.json).

후속 [TP-06](unity-throughput-optimization.md#tp-06-시간-비교)은 수정된 공유 Editor 재실행과 후속 최적화 후보의 회수 실패를 기록한다. 아래 과거 복구 포함 시간과 구분한다.

**양쪽 모두 복구를 거쳐 미로 기능, 실제 Play 검증, 결과 보존과 원본 소스 복원을 완료했습니다. 중단 없는 자동 처리 성능 벤치마크는 아닙니다.** 증거 복사만 제외하고 복구·진단을 포함한 관찰 전체 시간은 **Splinter 25분 1.9초**, **공유 Editor 13분 7.5초**입니다. 공유 실행에는 정확한 시작 시각을 기록하지 못한 재질 저장 모달 문제가 포함됩니다. 중단 없이 정상 처리했을 전체 시간은 **unknown**이며, 이 총시간으로 정상 전체 속도 비율이나 긴 작업 손익분기를 입증할 수 없습니다.

Splinter 보조 값에도 최초 timeout과 같은 작업공간 재시도가 들어갑니다. 첫 호출에 성공했을 처리량 값이 아닙니다. 이에 대응하는 공유 Editor 보정 총시간은 산출할 수 없습니다. 영향을 받은 476.4674초 전체, 추정 대화상자 시간, 인접 컴파일 시간을 임의로 빼서 값을 만들지 않습니다.

**Splinter 종료:** A/B에서 `workspace checkpoint --release`를 병렬 실행했습니다. 최초 호출은 121.7227초/121.8201초에 `EditorStopTimeout`을 반환했고, 두 Editor는 이후 약 130초에 정상 종료했습니다. 계측기가 프로세스 부재를 먼저 관측하고 비동기 정상 종료 영수증이 게시되기 전에 검사해 중단됐습니다. exit code 0 영수증을 확인한 다음 같은 workspace ID로 통합 명령을 다시 병렬 실행했고 약 128.1초/133.4초에 성공했습니다. 새 작업공간 대체나 강제 종료는 사용하지 않았습니다. 종료 구간은 원시 324.6650초이며, 따로 기록한 계측 중단 60.6813초를 빼면 263.9837초입니다. 주 총시간에는 해당 중단을 포함합니다. 로컬 `s-measurement-recovery.json`, 종료·재개 시간과 최초·재시도 응답이 근거입니다.

**공유 Editor 문제:** A2→B2 전환에서 A의 저장 자산을 A 코드 작업공간으로 돌려보낸 후 원본의 A 하위 트리를 제거했습니다. Unity가 캐시에 남은 Floor/Wall 재질을 삭제된 경로에 저장하려고 하면서 모달을 띄웠습니다. 소유 창을 확인한 뒤 Floor 2회·Wall 2회, 총 4개 모달을 취소했습니다. 그 전에 시도한 Escape 1회는 모달을 닫지 못했습니다. `q-b2` 컴파일·인계 476.4674초에는 모달 대기·조사·복구가 들어가며 순수 컴파일 시간이 아닙니다. 정확한 모달 시작 시각은 unknown입니다. 이후 외부 `idle-scene` fixture만 미사용 객체를 해제(`EditorUtility.UnloadUnusedAssetsImmediate`)하기 전후에 자산을 저장하도록 보완했습니다. A/B 기능 스냅샷은 바뀌지 않았습니다. 문제 대응 시간은 주 총시간에 모두 남겼습니다. 로컬 `q-modal-recovery.json`이 근거입니다.

## 입력과 고정 작업

양쪽은 Unity 6000.3.22f1, 소스 revision `b09fa58e9d40a560d4fe1af7a213f8ac23e8e3b1`, **추적 파일 1,602개 / 2,804,772,822바이트**, 같은 초기 **Library 42,416개 파일 / 3,141,770,387바이트**를 사용했습니다. Library 목록 SHA-256은 `8bb1eb3171651cf6c67efbf556c787126feaa687db36c8d18d4dd71d490df30e`입니다. 고정한 제품 소스·런타임 hash는 `07bc2de`와 일치합니다. 재사용 런타임은 해당 커밋 전에 빌드됐으며 새 빌드라고 주장하지 않고 기록된 hash로 식별합니다.

두 에이전트가 A/B를 병렬로 한 번 작성했습니다. 양쪽에서 정확히 같은 누적 기능 스냅샷을 재적용하고 편집마다 실제 컴파일·Editor 실행을 수행했습니다. AI 추론, 한 번 수행한 기능·harness 개발, 선행 진단은 방식별 시간에서 제외합니다. 이는 기능 차이를 통제한 비교이며 독립적인 AI 개발 세션 두 개를 측정한 것은 아닙니다.

## 실행 방식과 단계 비용

Splinter는 Library 기준본을 준비하고 A/B 작업공간을 동시에 생성한 뒤 독립 Editor 두 개를 시작합니다. A1→A2→A3과 B1→B2→B3을 병렬 수행하고 준비된 A Editor에서 통합합니다. 최종 A/B 통합 checkpoint/release도 정상 Editor 종료를 포함해 병렬 실행한 다음 원본 Library를 복원합니다.

공유 방식은 일반 코드 작업공간 두 개와 원본 Editor 하나를 사용하며 **A1→B1→A2→B2→A3→B3** 순서로 실행합니다. 전환 전에 생성 자산·메타데이터를 해당 작업공간으로 돌려보냅니다. B를 독립 보존한 뒤 공유 Editor에서 A/B를 합쳐 검증합니다. 양쪽 모두 **B 독립 결과와 통합 기능, 두 결과**를 보존합니다. 코드 작업공간은 스크립트로 만든 Git worktree이며 새 Codex 대화를 생성한 것은 아닙니다.

표는 반올림 값이며 작은 명령 전달·관측 간격은 총시간에 남습니다. 증거 복사는 별도로 뺐습니다. 입력 hash, 최종 감사, 앞선 진단 실행과 복구는 이번 총시간 밖입니다. 위에서 설명한 정식 실행의 복구는 포함합니다. 인위적인 작업 시간 지연은 추가하지 않았습니다.

Splinter 내부에서 A의 세 단계 합은 284.6초, B는 382.7초이며 382.9초 개발 구간 중 약 284.4초가 중첩됐습니다. 이번 실행의 병렬 Editor 작업을 확인한 값이며, 공유 방식 대비 같은 크기의 절감으로 읽지 않습니다. 공유 큐 대기에도 모달 문제가 포함되므로 정상적인 Editor 점유 경쟁의 측정값으로 해석하지 않습니다.

## 기능 결과와 종료 확인

6개 기능 단계와 양쪽 통합 Play 절차가 명시한 합격 검사를 통과했습니다. Play는 공개 가상 키보드 이벤트와 일반 키보드 이동에 쓰는 동일한 `CharacterController.Move`를 사용하며 실제 물리 충돌과 진입·목표 trigger를 처리합니다. 자동 경로 이동은 저장된 칸 중심을 목표로 삼고 명시적 재시작에서만 위치를 초기화합니다. 벽 차단은 sandbox에서 검증했으며 통합 진행은 열린 통로를 따라가므로 모든 미로에서 별도 고의 벽 충돌 시험을 했다고 주장하지 않습니다.

양쪽은 `playModeExited=true`, `inputSettingsRestored=true`를 보고했습니다. fixture는 원래 Input System 설정·백그라운드 선택을 복원하고 임시 설정 복제본과 소유 가상 키보드를 제거합니다. 정식 로그에서 이전 Input System 종료 assertion은 **0건**입니다. 통제한 Play 입력의 자격이며 수동 OS 포커스·물리 키보드 동작이나 일반 외부 도구 지원의 자격은 아닙니다.

생성 자산 GUID·장면 로컬 ID는 양쪽에서 다를 수 있습니다. 미로 내용 hash·장면 참조·같은 게임 동작 결과로 의미상 동등성을 확인하며 생성 장면 바이트가 같다고 주장하지 않습니다. 실제 확인한 미리보기 PNG 두 개는 SHA-256 `e7b499179ee71dadaffca444408c0d20ac5d6e58673e96719ecea5e10a6d7a5f`로 같습니다. 이 일치는 해당 렌더 출력 한 장에 한정합니다.

소유 Editor 세 개 모두 exit code 0으로 정상 종료했습니다. Splinter 작업공간 둘은 `released`가 됐고 소유 provider·mount·delta와 활성 프로세스·메모리 관측을 회수했습니다. 원본 소스는 clean 상태를 유지하거나 복원했으며 추적 파일 1,602개의 바이트를 확인했습니다. 브랜치·설정·기존 ref와 worktree 등록을 보존했습니다. 실제 CLI 응답 15개가 현재 schema를 사용하는 Release 검증 시험 1개를 통과했습니다.

공유 방식은 종료 전에 원본 게임 소스를 복원·재컴파일했습니다. 외부 관측 스크립트만 완료 확인·종료를 위해 남겼다가 종료 후 제거했으므로 이후 관측 코드만 제거하는 Editor 어셈블리 재컴파일 가능성을 배제하지 않습니다. Splinter는 Q 시작 전에 원본 Library를 바이트 단위로 복원했습니다. Q 이후 정상 재생성된 Library cache는 유지했으며 이후 cache까지 같다고 주장하지 않습니다.

**Console 전체가 깨끗하다는 주장은 하지 않습니다.** Unity Search 인덱싱 `ArgumentOutOfRangeException`이 A 1건·B 2건이며 FontEngine/TMP callback 해제 메시지는 A·B·Q 각각 1건입니다. 원인은 확정하지 않았습니다. 지정한 게임 검사의 성공, 별도 Input System assertion 0건, 정상 종료와 남은 메시지는 구분한 관측입니다.
