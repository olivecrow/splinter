## WP-01 — 변경 없는 명시적 flush 재사용

SJR2는 `Flush(true)` 성공 뒤에만 핸들과 길이를 기록한다. 명시적 `Flush()`는 로컬 무결성을 확인하고 같은 핸들·같은 길이일 때만 그 결과를 재사용한다. 회수 기록은 sequence를 늘리지 않고 추가될 수 있고 checkpoint 게시는 stream을 교체하므로 sequence만으로 판단하지 않는다. 신규/재연결/교체 핸들은 자체 영속 경계를 확인한다. 변경/묶음 flush·불확실한 쓰기의 poison·접수 ticket drain·`flush.before/after` 관측 경계·SJL4 게시/명시적 flush는 유지한다. 일반 순차 쓰기 하나도 성공 전에 계속 flush한다. 이번 개선은 호출자가 이미 영속화된 바이트에 다시 명시적 flush를 요청할 때 적용된다.

시험은 신규/재연결 append·bounded·latest 모드, 반복 명시적 flush, 중간 쓰기, readback, 기준본 부재를 확인한다. 기존 순서/실패 묶음·중단 대기자·명시적 flush ticket drain·checkpoint/복구 시험은 유지하며 물리 횟수 기대값에서 중복 barrier만 제외했다.

## WP-02 — payload 읽기 없는 상태 크기 계산

현재 상태 출력은 raw이므로 예상 크기는 decoded 길이로 계산하고 payload 읽기/할당을 생략한다. Metadata 직렬화와 한도는 유지한다. 실제 출력은 payload를 읽고 checksum을 기록하며 예상/실제 크기 비교와 전체 후보/게시 상태 증명·복구 검사를 통과해야 한다. Raw·현재 형식 압축 fixture에서 크기 계산 읽기 0·예상/출력 길이 일치·실제 출력 읽기를 확인했다. 저널 형식이나 reader 이관은 바꾸지 않았다.

크기 계산 단계 자체는 크게 빨라지고 payload 크기만큼의 불필요한 할당을 제거한다. **전체 checkpoint가 크게 빨라졌다는 뜻은 아니다.** 아래 최종 checkpoint 중심 부하의 개선은 **3.555%**이며 전체 상태 출력과 검증이 여전히 지배한다.

## WP-03 — 탈락한 raw 양끝 탐색

후보는 raw private 덮어쓰기의 양끝 차이를 찾아 정확한 연속 변경 범위를 유지하고 변경되는 가운데 읽기를 생략했다. 한정 정확성 시험은 통과했다. 전후후전 비교에서 256 × 1MiB 덮어쓰기 평균은 **1.838353 → 1.882652초**, 저널 읽기는 **321,912,832 → 69,206,016바이트**였다. I/O 감소가 시간 이점으로 이어지지 않아 구현과 후보 전용 시험을 제거했다. 실행 파일과 원시 측정은 근거 디렉터리에 보존하며 선택적 backend나 채택한 최적화가 아니다. 기존 raw/압축 비교와 4KiB 기준은 유지한다.

## WP-04 — 최종 동일 입력 비교

같은 probe 실행 파일에 보존한 기준/최종 Core·Runtime 어셈블리를 각각 연결했다. 닫힌 입력 파일·identity·hash를 재사용하고 각 실행의 별도 복제는 타이머 밖에서 수행했다. 최종 순서는 **전 → 후 → 후 → 전**, 각각 두 번이며 빌드/시험/probe를 겹치지 않았다. 입력은 생성된 빈 파일, 고정 seed의 1MiB 파일, 16MiB live 파일과 4,096-frame checkpoint 경계의 작은 append 파일이다. 모두 기본 16MiB/4,096-frame 한도의 bounded SJR2다. 묶음은 명시적으로 공급했으며 Unity의 실제 요청 기록이 아니다.

크기 계산 읽기는 **275,771,904 → 0바이트**, 누적 관리 할당 평균은 **335,996,436 → 59,337,904바이트**다. Checkpoint 부하의 읽기는 **104,790,720 → 69,860,480바이트**, 할당은 **148,880,144 → 113,957,860바이트**다. 이는 측정 구간의 누적 할당이며 보유 메모리나 전체 프로세스 peak RAM이 아니다. 덮어쓰기 결과는 checkpoint 크기 계산 개선을 포함하지만 비교 알고리즘은 기존 그대로이며 작은 개선을 새 큰 속도 이점으로 주장하지 않는다.

최종 Runtime SHA-256은 `94e646cfad3a8a35654d312bc54f5a33758498dfd1f41f2b14f73426f357f428`, 기준 Runtime은 `b9751fe7be66bd428457d0daea51ef68991414ec9eb6445f24c756bd1857222c`다. 데이터셋은 원시 파일·어셈블리·소스 hash를 기록한다. 측정 뒤 독립 검증기로 후보/최종 비교의 **재생 파일 56개** 예상 길이와 모든 바이트를 확인하고 고정 입력 hash도 다시 확인했다. Fake 기준본은 payload 읽기를 허용하지 않는다.

남은 비용: 최종 개별 쓰기+명시적 flush **4.374668초** 중 물리 flush가 **4.317677초**, 2,048개 쓰기 전체 준비는 **0.033705초**다. 준비 스레드나 새 binary metadata 형식은 이 측정의 지배 비용을 해결하지 못한다. Checkpoint 부하에서는 전체 **0.993840초** 중 checkpoint가 **0.707720초**다. 전체 private 상태 재작성/증명/게시가 구조적 병목이며 다른 증분 checkpoint 표현은 별도 형식/복구 작업이 필요하다. 준비 계수에는 중첩 checkpoint가 포함되므로 이 계수들을 서로 더하면 안 된다. 내구성 계약을 바꾸거나 일반 작업량의 속도 개선을 증명한 결과는 아니다.

## WP-05 — 회귀와 근거 한계

`pwsh -NoProfile -File scripts/build.ps1`의 locked restore·Release 빌드가 **경고/오류 0개**로 통과했다. 최종 전체 시험은 **전체 1,626 / 통과 1,598 / 실패 0 / 건너뜀 28**, 요약 시간 **535.407초**다. `final-gate.log` / `final-gate.trx`를 보존하고 데이터셋에 hash를 기록했다. 아래 기존 공유 시험도 전체 검증에서 통과했다. 최종 Runtime hash는 측정 실행 파일과 일치하며 최종 비교 뒤 제품/시험 코드는 바꾸지 않았다.
