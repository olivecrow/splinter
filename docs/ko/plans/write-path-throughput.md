# 쓰기 경로 처리량

[English](../../plans/write-path-throughput.md)

사용자는 2026-10-25 `9594209`의 쓰기 경로 검토 후 최적화 후속을 승인했다. 큰 시간 절감을 우선하고 raw 범위 저장·영속 완료 뒤 성공을 유지하며, 구조를 더 복잡하게 바꾸기 전에 같은 입력으로 비용을 비교한다.

- WP-01: 같은 열린 SJR2 저널의 변경 없는 바이트가 이미 영속 flush에 성공한 경우에만 중복 명시적 flush를 생략한다. 재연결·교체·실패·접수된 대기 쓰기의 경계를 유지하며 SJL4 게시 절차는 그대로다.
- WP-02: raw 상태 frame 크기를 payload 읽기/할당 없이 계산한다. 실제 출력·checksum·전체 상태 증명·후보/게시본 replay·checkpoint 복구는 유지한다.
- WP-03: private 덮어쓰기의 같은 앞뒤 부분을 양끝에서 찾고 변경된 가운데는 읽지 않는다. 전체 private 범위의 수용 검사·정확한 변경 구간·4KiB 재사용 임계값·현재 압축 reader·손상 처리를 유지한다.
- WP-04: 고정 합성 쓰기/flush·checkpoint·덮어쓰기 입력에서 보존한 기준/후보 실행 파일을 비교한다. 단계 시간·물리 flush·저널 읽기 바이트·관리 할당·전체 replay 확인을 포함한다. 준비 병렬화와 형식 변경은 결과로 판단하며, 가능하다는 이유만으로 작은 효과의 동시성·schema 변경·폐기 backend를 추가하지 않는다.
- WP-05: 회귀 시험·필수 locked Release 빌드/전체 시험·양 언어 현재 계약·근거 기록. Unity 수명주기·원본 프로젝트 작업·전원 장애 행렬·장치 변경·자동 커밋/푸시는 없다.

새 측정은 한정 구성 요소이며 마감한 Unity/DF 실험을 반복하지 않는다. 기존 16MiB/4,096-frame suffix 한도·형식 버전·원본/peer/독립 결과 보호·전체 파일 copy-up 금지를 유지한다.

결과: WP-01/02를 채택했다. WP-03 양끝 탐색 후보는 읽기 감소가 전체 덮어쓰기 시간 절감으로 이어지지 않아 제거했으며 선택적 제품 경로가 아니다. 후보와 최종 비교는 [WP 검증](../verification/write-path-throughput.md)이 소유한다. 작은 쓰기의 CPU 비용이 작게 측정되어 준비 스레드와 새 metadata/checkpoint 형식은 추가하지 않았으며, 전체 checkpoint 게시는 별도 구조적 비용으로 남는다.
