# 영속 flush와 종료 처리량

[English](../../plans/durable-flush-throughput.md)

사용자가 flush/종료 검토에서 찾은 최적화 구현을 승인했다. 기준은 `663c400`이다. 한 작업공간의 쓰기·최종화 비용을 대상으로 하며 A/B 실행 순서 변경이나 중단한 Unity 종료 진단의 재개가 아니다. **판단: 제품 채택 없이 완료.** 큰 절감 기준을 충족하지 못한 준비 frame 후보는 제거했으며 개별 flush와 현재 제품 동작을 유지한다.

| ID | 범위와 완료 기준 |
| --- | --- |
| DF-01 | 고정한 작은 NTFS 영속 쓰기 입력을 순차 비교한다. 실제 flush 완료·할당·내용 검증을 포함하며 제품 I/O 변경을 고르기 전에 대안을 측정한다. |
| DF-02 | bounded 상태 checkpoint 준비 결과를 연산 한정 RAM에서 재사용한다. 정확한 크기/출력·전체 논리/물리 증명·개별 durable ACK·실패 writer 차단·세대 소유권·복구를 유지한다. 큰 상태에는 제한된 fallback을 둔다. |
| DF-03 | 같은 입력의 전후후전 구성 요소 비교로 자동 checkpoint와 재생/종료까지 측정한다. 해당 작업의 큰 절감을 우선하며 작은 I/O 측정을 Unity 속도로 확대하지 않는다. |
| DF-04 | 손상·중단·예산 집중 회귀와 필수 locked restore/Release 빌드·시험을 실행한다. |
| DF-05 | 양 언어 구현/검증 문서, 정확한 수치와 미실행 경계를 기록한다. |

실험은 새 소유 임시 파일과 `artifacts/durable-flush-20261024/`의 보존 근거만 사용한다. 원본 프로젝트·Unity 실행·설치 도구/서비스/디스크 쓰기 cache 설정·기존 프로세스·과거 근거 회수를 변경하지 않는다. 요청별 내구성, 16MiB/4,096-frame 한도와 기존 디스크 형식은 유지한다. 상위 요청 중첩이 확인되지 않았고 별도 순서 계약이 필요한 group commit과 비동기 조기 ACK는 제외한다. 직접 I/O 후보는 내구성/형식/메타데이터 요건을 증명하기 전 제품에 채택하지 않는다. 실패 후보는 근거로만 남기며 선택적 제품 backend가 아니다.

Unity 전체 종료·원본 반영·OS 전원 장애·다른 저장 장치·전체 peak RAM은 별도 자격이다. 측정 중 빌드나 다른 probe를 겹치지 않는다. [검증 기록](../../verification/durable-flush-throughput.md)에 실측 결과와 채택 여부를 기록했다. 미완료 제품 작업이나 자동 재실행 요청이 아니다.
