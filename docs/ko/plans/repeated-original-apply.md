# 같은 작업공간의 반복 원본 반영

[English](../../plans/repeated-original-apply.md)

2026-10-30 승인 범위다. Git·일반 폴더·기록된 Plastic 작업공간에서 원본과 작업 Editor를 유지하며 불변 결과 세대를 수집하고 원본에 반복 조건부 게시한다. 기존 검증 프로그램을 재개하지 않는다.

중간 절차는 외부 Unity 도구로 작업 저장 → 불변 독립 결과 수집 → 원본 저장 → 고정한 전체/선택 계획 검토·게시 → 안전한 refresh/재로드 → 같은 작업 지속이다. 최종 절차는 해당 작업만 저장·정상 종료한 뒤 같은 수집·게시 엔진을 사용하고 명시적으로 회수한다. 원본과 peer Editor는 유지한다.

수집은 짧은 mutation 경계에서 접수된 소스 상태를 고정하고, 저널 교체·절단을 영속적으로 보호한 뒤 경계 밖에서 payload를 보존한다. 요청 키는 응답 유실·재시작 뒤에도 동일한 한 세대만 가리킨다. 독립 결과는 회수 뒤에도 보존한다. 원본 게시는 경로별 마지막 반영 상태·새 결과·현재 원본을 비교하며 작업공간의 불변 기준본을 바꾸거나 원본 변경을 가져오지 않는다.

Git 원본 게시에는 HEAD·index·branch·무관한 편집을 보존한다. 기존 명시적 branch merge는 clean-target 계약을 유지한다. 결과·intent·digest를 명시하며 실행 중 원본에는 정확한 Editor에 결합한 외부 협력 허가가 필요하다. Unity 잠금 검사만 제거하지 않는다. 저장·import/reload 유예와 해제·refresh·컴파일·로드 결과 판단은 외부 도구와 에이전트가 맡는다. 원본 전용 패키지나 제품 내부 외부 도구 runner는 추가하지 않는다. 기존 경로의 dirty 씬·에셋을 저장하며 이름 없는 씬·Play·저장 실패/불명은 보존·중단한다. 게시 중 생긴 영향 경로의 dirty 편집을 강제 재로드하지 않는다.

작업공간 상태는 새 현재 버전으로 올리고 자동 이관하지 않는다. v2 작업·결과는 일치하는 이전 바이너리용으로 보존한다. 지원 raw 저널·영속 ACK·원본/peer identity·metadata·동반 파일·미완료 intent·정확한 회수 보호를 유지한다. VSS/ReFS·전체 복제/hydration/copy-up·자동 merge/commit/check-in·Play/build·설치기·서버 수명 관리는 제외한다.

구현 순서는 계약/복구 시험 → 실행 중 수집 → 독립 세대 → 반복 게시/Git → 외부 도구 절차 → 입력별 고정 실제 Unity 원본/A/B 한 묶음 → 최종 전체 gate다. [검증](../verification/repeated-original-apply.md)의 RI-01–08이 완료를 소유한다. 필수 실제 행은 과거 통과나 skip으로 대체하지 않는다. 비용 관측은 속도/RAM 절감 주장이 아니다.

2026-10-30 상태: **한정 완료**. 세 입력 각각 실제 원본/A/B 한 묶음·반복 실행 중 게시·최종 종료 쓰기·원본 생존 중 회수·현재 cm reader·최종 전체 gate를 포함해 RI-01–08을 기록한 범위에서 통과했다. 복구한 실패·비용·미검증 경계는 검증 소유 문서에 유지하며 추가 입력이나 마감한 성능 실험을 재개하지 않는다.
