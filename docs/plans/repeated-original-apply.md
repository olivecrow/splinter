# Repeated original application from a continuing workspace

[한국어](../ko/plans/repeated-original-apply.md)

Approved 2026-10-30. This unit extends Git, ordinary-folder and recorded Plastic workspaces with immutable result generations and repeated conditional original publication while the original and task Editors remain running. It does not reopen earlier qualification programs.

Intermediate workflow: save the task through existing external Unity tools, capture an immutable independent result, save the original, review and publish a fixed full/selected plan, refresh/reload safely, and continue the same task. Final workflow: save and normally stop only the task Editor, use the same capture/publication engine, and explicitly reclaim the task. Original and peers remain running.

Capture fixes acknowledged source state under a short mutation boundary. Payload preservation runs outside that boundary with durable protection against journal replacement/truncation. Every request key identifies exactly one generation across lost responses and process restart. Results remain independent and preserved after task reclamation. Original publication compares a per-path applied baseline with the new result and current original; it does not change the immutable workspace basis or import original changes.

Git original publication preserves HEAD/index/branch and unrelated edits. Existing explicit branch merge retains its clean-target contract. Original publication requires explicit result/intent/digest and an exact live-Editor external-cooperation permit when appropriate; removing the Unity lock check alone is prohibited. External tools/agents own saving, import/reload deferral and release, refresh, compilation and loaded-state judgment. No original integration package or internal external-tool runner is added. Named dirty scenes/assets are saved; unnamed scenes, Play, failed or uncertain saves preserve and stop. New dirty affected content must not be forcibly reloaded.

Current workspace state is versioned forward without automatic migration. Retain old v2 tasks/results for their matching old binary. Retain supported raw journal modes, durable acknowledgements, original/peer identity, metadata, companion, incomplete-intent and exact reclamation protections. No VSS/ReFS revival, full project clone/hydration/copy-up, automatic merge/commit/check-in, Play/build, installer or server lifecycle management.

Implementation order: contracts/recovery tests; live capture; independent generations; repeated publication/Git; external-tool procedure; one fixed actual Unity original/A/B set per source; final full gate. [Verification](../verification/repeated-original-apply.md) owns RI-01–08. Required native rows cannot inherit earlier passes or be replaced by skips. Cost observations are not speed/RAM-saving claims.
