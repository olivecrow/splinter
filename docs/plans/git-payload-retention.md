# Git payload retention

[한국어](../ko/plans/git-payload-retention.md) · [Verification](../verification/git-payload-retention.md)

This follow-up tested whether retaining more already-verified Git payload reduced one workspace's creation time. Native ABBA means were **50.661 → 48.550s**, saving **2.111s (4.2%)**, while mean provider lifetime peak working set rose **0.675 → 2.768GiB**. The candidate was rejected because this did not meet the requested substantial time-saving criterion; the product contract remains **256MiB / 4,096 entries**. [BD-01](../verification/unity-lifecycle-bottleneck-diagnosis.md) observed 2,913,936,481 bytes decoded again after completed proofs and 2,027,356,160 unused read-ahead bytes evicted during preparation. Those counters motivated the experiment; they did not establish an equivalent elapsed-time saving. Earlier [WC-01–05](../verification/workspace-creation-throughput.md) and BD-01 measurements remain separate evidence.

The tested candidate raised the per-tree retained-payload limits from **256MiB / 4,096 entries** to **1.5GiB / 32,768 entries**. It increased both bounds because retaining more bytes alone left small chunks constrained by the entry count. Allocation remained on demand, and eviction preceded allocation using a subtraction-based capacity comparison. It introduced no 1.5GiB reservation at construction, configurable 2GiB mode, new storage format or compatibility path. These experimental limits are not a supported product option.

The candidate preserved two decoder sessions, the 128MiB forward-proof window, the separate 4MiB proof budget, whole-object verification, current retained-chunk hashes, health checks, failed-reader publication exclusion and close/drain. Initial warm reads and mandatory index refresh still overlapped and joined on success, failure and cancellation. Their ordering and LRU policy were unchanged. No cache-wait bypass, additional reader, disk cache, full input copy, skipped refresh/proof or relaxed flush/ACK was introduced. No consumption-order/LRU policy trial was run, and this record does not authorize an automatic follow-up.

GR-01 uses dedicated experiment source commit `20967120692904985ea6320ce01f93239ba136ff`: **1,602 source files / 2,804,769,296 bytes**, plus **42,038 Library files / 3,105,800,655 bytes**. The experiment clone and copied old Library cache are setup outside timing; product preparation still forbids full input copying. Compare identical complete bytes, modification times and attributes. Time each fresh `workspace ensure` with a monotonic stopwatch; separately report common Library preparation/restoration, input verification and each explicit private edit/discard. Enable the same G1 diagnostics and bounded observation in both variants. Failure stops the series and preserves the exact task/key/home/intent and evidence.

The experimental 1.5GiB limit bounded retained chunk bytes per tree, not total process or system memory. Proofs, index structures, decoder processes, request buffers and transient/garbage-collected allocations add costs. Provider lifetime peak working set and private commit are observations with different scopes from cache counters; they cannot establish whole-system peak RAM. GR-01 is one machine, two observations per variant, without clearing OS caches. The old Library cache is not asserted warmed for this fixture source. GUI startup, compilation, Play/Test/build, original apply, power-loss behavior and a whole Unity lifecycle comparison are outside this experiment. No new gain follows merely from fewer decoded bytes.

All four tasks were explicitly discarded and their owned providers exited. Complete source/Library bytes, modification times, attributes and source Git metadata matched after every trial and final restoration to ordinary NTFS. Common Library preparation took 40.585s and restoration 22.621s, each once outside the ensure comparison. The sampler reported no read errors, failure or limit exhaustion. Candidate source/tests are archived locally and removed from the product; all final source/test files match `bea4acd`. The restored solution rebuilt with zero warnings/errors, and focused Git cache/reader/read-ahead/diagnostic tests passed **56 / 0 failed / 1 conditional skip**. The earlier BO full gate belongs to that unchanged source; the 1,734-test gate above belongs to the rejected candidate.
