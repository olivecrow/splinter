## 목표와 현재 근거

Splinter는 각 대화의 AI가 필요할 때 독립 작업공간을 만들고 여러 차례 작업을 이어 간 뒤 명시적으로 반영·보존·폐기하도록 하는 도구다. 우선순위는 **대형 Unity 프로젝트의 추가 저장공간 감소**, 그다음 Editor 동시 실행이다. 기존 NTFS 원본의 위치·지속 편집, 작업 시작 시점의 불변 기준, 최초 전체 복제·읽기 hydration·파일 전체 copy-up 금지와 독립 결과 보존을 유지한다.

## 계측 계약

- 실행 중 일관되지 않은 저널을 직접 읽어 확정 수치로 쓰지 않는다. Editor와 쓰기 client가 정지하고 provider가 unmount된 경계의 seal·sequence에 장부를 묶는다. 정리 후 저널의 sequence와 형식을 이해하는 기존 replay를 사용하며 원본 payload 복사·별도 정리 후보 생성을 분석 수단으로 추가하지 않는다.
- 경로군별 누적 payload, 현재 유효 payload와 제거 가능한 과거 기록은 **논리 바이트 분류**다. 하나의 저널 파일에 섞인 `Library`의 물리 할당을 임의 비율로 추정하지 않는다. 실제 할당은 delta/임시 세대, control/runner/log, 기준 대비 Git 객체·독립 결과를 겹치지 않게 센다. mount view와 저널 내부의 Library를 다시 더하지 않는다.
- Git common의 생성 직전 기준을 합성·Unity 모두 확보한다. 표본은 같은 시각의 합계로 계산하고 서로 다른 시점의 최대값을 합산하지 않는다. 정리 전·후보 작성·게시·이전 세대 제거 경계를 별도 관측하고, 주기 표본 간격도 기록한다.
- VSS Used/Allocated는 격리 원본 볼륨의 공유 시계열로 표시한다. workspace별 비용에 귀속하거나 두 작업에 중복 합산하지 않는다. NTFS 디렉터리/MFT, 표본 사이 최고치 등 미계측은 unknown으로 남긴다. 전체 물리 공간이 완전히 측정되지 않았다면 그 절감률이나 상한을 선언하지 않는다.
- 쓰기별 flush 수·누적 지연과 scan/replay/seal/재연결 비용은 관측만 한다. 시간 감소와 저장량 감소를 별도로 판정한다. 현행 acknowledged write 내구성·`stable-journal-v1`과 제어 파일의 atomic 게시 계약을 유지한다.
- 계측 보완은 개발용 읽기 전용 도구에 둔다. 제품 입출력 계약 변경이 필요한 최소 결함 수정에는 schema·fake·적합성 시험·현재 계약 문서를 함께 갱신한다. 이번 계획만으로 새 명령이나 capability를 추가하지 않는다.

## 자원과 실행 순서

1. 기존 원시 증거·계측의 부족한 항목을 먼저 확인한다. 격리 합성 fixture 1개와 기존 작은 Unity fixture 1개만 사용한다. 두 작업을 순서대로 진행하고 시험용 Unity Editor는 동시에 최대 1개다. A/B 동시 실행·새 에셋 구매·대형 프로필은 포함하지 않는다.
2. 기존 시험 절차의 격리 NTFS 자원과 짧은 home을 사용한다. 원본·delta·Git의 볼륨을 명시하고 현재 소유권·여유 공간을 확인한다. 공간이 부족하면 보존하고 중단한다. 제품 예산은 물리 여유 공간 검사를 대신하지 않는다. 새 VHD 생성·관리자 준비가 필요하면 구체 경로·크기·소유 ID를 확정한 해당 권한 경계에서 처리한다.
3. 합성의 BQ-02를 먼저 닫고 Unity BQ-03/04로 진행한다. 첫 import와 반복 편집·정리·재개 비용을 분리한다. 기존 종료된 시험 workspace나 snapshot을 복구해 재사용하지 않으며 과거 원시 증거와 독립 결과를 보존한다.
4. `checkpoint`는 각 작업의 마지막 편집 뒤 한 번의 최종 수집으로만 사용한다. 이번 검증 결과는 원본 브랜치에 통합하지 않는다. 보존형 release를 사용하며 명시적 discard가 구현됐다고 설명하지 않는다.
5. 정확히 소유한 자원만 정리한다. VSS 순서 제약으로 `reclaim-pending`이면 완료로 기록하지 않고 동일 id/home의 명시적 release 재시도 절차를 따른다. 다른 snapshot 삭제·자동 sweep으로 우회하지 않는다. 일반 비소유 백업 공존이나 외부 동시 삭제 보장으로 확대하지 않는다.

Unity 실행 시 형제 fixture의 AGENTS.md도 읽고 원본 및 무관한 Editor/MCP 세션을 보존한다. 이 제품 검증에는 Coordination 스킬/패키지나 Codex 별도 worktree를 중첩하지 않는다. 마감한 PV의 C/S/Q 분리는 유지한다. 이번 범위는 별도 대화나 하위 에이전트의 병렬 실행을 요구하지 않는다.

## 제외 범위와 종료 판정

이번에는 flush 묶음 처리·쓰기 내구성 정책 변경, 자동/온라인 정리, 새로운 저널 형식·세그먼트 GC·중복 제거, 단일 Editor 제품 연결·후보 전환, 설치·자동 binding·discard·상주 권한 서비스·daemon/DB를 구현하지 않는다. SF-05/06의 대형 실사용 입력·기본 실행 방식 결정, 마감한 PV 재개, ReFS 확장과 일반 에셋/Play/Test 지원도 제외한다. 실제 재부팅·전원·물리 공간 고갈·ARM A/B 등 NR 지원 확대 관문은 별도 계획에 유지한다.

실행 증거는 `artifacts/storage-foundation/<runId>/`의 후보/입력 manifest, CLI 응답, journal 분류·공간 시계열, Unity loaded-code, 결과·회수 영수증으로 보존한다. [별도 검증 문서](../verification/journal-budget-and-growth-qualification.md)를 만들고 이 계획 및 검증 추적표에서 연결했다. BQ-01~05가 정의한 수준에서 충족돼야 이 작은 실행 단위를 완료로 기록한다. 부분 실행·실패·운영 개입은 해당 관문에 그대로 남긴다.

BQ의 정의한 제품 예산·작은 Unity·장부·보존/회수 범위는 운영 재시도와 계측 개입을 포함해 완료했다. **공통 저장소 1차 FailedPreservation, SF-01의 정의한 소스 검증 Passed, SF-02 전체 Partial, SF-03~06 NotRun**은 유지한다. SF-03을 다음 후보로 선정한 것은 단일 Library의 실제 절감이나 기본 모드 채택의 증거가 아니다.
