Parallel workspaces on Windows / NTFS · Product goals independent of external VCS availability

AI creates parallel workspaces efficiently and discards them when requested

Splinter is a local tool for development environments such as Unity, where project and Editor occupancy limit independent work. The AI in each conversation creates its own task when needed and continues it across multiple rounds. That AI and existing development tools handle decisions about the work, editing, and game functionality verification.

2. Usage flow and lifetime

Create/resume when needed → Edit independently and use the necessary Editor → Preserve / Explicitly apply then reclaim / Explicitly discard

The AI's file tools, CLI, and Editor use the same task at the returned workspace path. If a task is already connected, continue that task even when the original becomes available. A separate coordinating AI, nested Codex worktree, and work-graph submission are unnecessary.

Conversation or Editor termination, timeouts, lease expiry, and disk pressure do not authorize integration or discard. Release preserves an independent result. Discard compares explicit intent and exact ownership to remove only that task, even without successful verification or a checkpoint. Shared view/cache/snapshot dependencies return a block and next actions, without automatic cascading deletion. Distinguish pending reclamation from completion.

4. First-version completion criteria

Two actual AI tasks create independent workspaces in the same project, edit repeatedly, and perform necessary Unity verification. Preserving or discarding one task keeps the other task and the original intact. The same task can resume; space/time costs determine usability under those conditions.
